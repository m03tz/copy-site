    **lib/actions/medical-records.ts:**
    Follow the exact pattern from appointments.ts (Zod schema, createClient, role check, getDoctorId helper).

    Create `createVisitRecord(formData: FormData)`:
    - Zod schema: patient_id (uuid required), appointment_id (uuid optional -- supports walk-ins per user decision), visit_date (date string YYYY-MM-DD required), notes (string optional -- "notes only" per user decision)
    - Role check: only doctor or secretary can create (per user decision)
    - Get doctor_id via the same getDoctorId helper pattern used in appointments.ts
    - Insert into medical_records: patient_id, appointment_id (null if not provided), doctor_id, visit_date, notes. Do NOT populate chief_complaint, diagnosis, treatment_plan, vital_signs (user decided "notes only")
    - revalidatePath for doctor/secretary patient pages and patient records
    - Return { success: true, record } or { error: string }

    Create `updateVisitRecord(formData: FormData)`:
    - Accepts record_id (uuid), notes (string optional), visit_date (date string)
    - Role check: doctor or secretary (user decided "Visit records are always editable")
    - Update the medical_records row by id
    - revalidatePath
    - Return { success: true } or { error: string }

    **lib/actions/prescriptions.ts:**
    Create `createPrescription(data: { medical_record_id: string, patient_id: string, medications: Array<{ medication_name: string, dosage: string, duration: string, instructions?: string }> })`:
    - Zod schema validates: medical_record_id (uuid), patient_id (uuid), medications array with min 1 item, each item has medication_name (min 1), dosage (min 1), duration (min 1), instructions (optional)
    - Role check: only doctor can create prescriptions
    - Get doctor_id
    - Insert all medications as separate prescription rows (one row per medication, all sharing same medical_record_id) -- this matches the schema where prescriptions table has one row per medication
    - revalidatePath
    - Return { success: true } or { error: string }

    CRITICAL: Prescriptions are per-medication rows. A "prescription" with 3 medications creates 3 rows in the prescriptions table, all sharing the same medical_record_id.

<task type="auto">
  <name>Task 2: Create file management and patient search server actions</name>
  <files>
    lib/actions/files.ts
    lib/actions/patients.ts
  </files>
  <action>
    **lib/actions/files.ts:**
    Create `uploadFile(formData: FormData)`:
    - Extract: file (File), patient_id (string), medical_record_id (string) from FormData
    - Role check: doctor or secretary only
    - Validate file type server-side: only allow image/jpeg, image/png, image/webp, application/pdf
    - Upload to Supabase Storage bucket 'patient-files' with path: `{patient_id}/{medical_record_id}/{Date.now()}-{file.name}`
    - Insert record into patient_files table: patient_id, medical_record_id, uploaded_by (user.id), file_name (original name), file_type ('image' or 'pdf' based on MIME), file_path (storage path)
    - On DB insert failure: rollback by deleting the uploaded file from storage
    - revalidatePath
    - Return { success: true } or { error: string }

    Create `deleteFile(fileId: string, filePath: string)`:
    - Role check: doctor or secretary (per user decision "Both doctor and secretary can delete uploaded files")
    - Delete from Supabase Storage: supabase.storage.from('patient-files').remove([filePath])
    - Delete from patient_files table by id
    - revalidatePath
    - Return { success: true } or { error: string }

    Create `getFileUrl(filePath: string)`:
    - Create signed URL with 1 hour expiry: supabase.storage.from('patient-files').createSignedUrl(filePath, 3600)
    - Return signed URL string or null on error

    **lib/actions/patients.ts:**
    Create `searchPatients(query: string, page: number = 1, perPage: number = 12)`:
    - Build Supabase query on profiles table: select profiles + patients (inner join via patients!inner)
    - Filter: role = 'patient'
    - If query is not empty: use .or() with ilike on full_name_ar, full_name_en, phone
    - Order by full_name_ar ascending (per user decision "Default sort: alphabetical by patient name")
    - Pagination: .range((page-1)*perPage, page*perPage-1) with { count: 'exact' }
    - Return { patients, count, page, perPage } or { error: string }

    Create `updatePatientInfo(formData: FormData)`:
    - Extract: patient_id, full_name_ar, full_name_en, phone, email, date_of_birth, blood_type, national_id, emergency_contact_name, emergency_contact_phone, notes
    - Role check: doctor or secretary (per user decision "Both doctor and secretary can edit patient personal information")
    - Zod validation for all fields
    - Update profiles table: full_name_ar, full_name_en, phone, email
    - Update patients table: date_of_birth, blood_type, national_id, emergency_contact_name, emergency_contact_phone, notes
    - revalidatePath
    - Return { success: true } or { error: string }
  </action>

    - patients.ts uses .ilike for search and .range for pagination
  </verify>
