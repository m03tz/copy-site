  <action>
Rewrite `lib/types/database.ts` to match `supabase/migrations/00001_initial_schema.sql` exactly. The current file has numerous mismatches. Key changes:

**Enums/types to fix:**
- `AppointmentStatus`: Remove 'no_show', keep 'scheduled' | 'confirmed' | 'completed' | 'cancelled'
- `PregnancyStatus`: Change from 'active' | 'completed' | 'terminated' to 'active' | 'delivered' | 'miscarriage' | 'ectopic'
- Add `AppointmentType`: 'consultation' | 'follow_up' | 'prenatal' | 'ultrasound' | 'other'
- Add `FileType`: 'image' | 'pdf'

**profiles table - fix fields:**
- Remove: `full_name`, `phone_number`, `date_of_birth`, `national_id`
- Add: `full_name_ar` (TEXT NOT NULL), `full_name_en` (TEXT | null), `phone` (TEXT NOT NULL), `email` (TEXT | null)
- Keep: id, role, created_at, updated_at

**patients table - fix fields:**
- Remove: `profile_id`, `updated_at`, `medical_history`, `allergies`, `address`, `city`
- The PK `id` directly references profiles(id) -- there is no separate `profile_id`
- Add: `date_of_birth` (DATE NOT NULL), `notes` (TEXT | null)
- Keep: id, blood_type, national_id, emergency_contact_name, emergency_contact_phone, created_at

**appointments table - fix completely:**
- Remove: `scheduled_at`, `duration_minutes`, `reason`, `cancelled_at`, `completed_at`, `updated_at` (wait -- updated_at exists in SQL, keep it)
- Add: `doctor_id` (UUID NOT NULL), `scheduled_start` (string/TIMESTAMPTZ), `scheduled_end` (string/TIMESTAMPTZ), `appointment_type` (AppointmentType), `created_by` (string | null)
- Keep: id, patient_id, status, cancellation_reason, notes, created_at, updated_at

**Add entirely new tables:**

`doctor_schedule`:
- Row: id (string), doctor_id (string), day_of_week (number 0-6), start_time (string/TIME), end_time (string/TIME), slot_duration_minutes (number, default 30), is_active (boolean), created_at (string)
- Insert: id optional, doctor_id required, day_of_week required, start_time required, end_time required, slot_duration_minutes optional (default 30), is_active optional (default true), created_at optional
- Update: all optional

`doctor_holidays`:
- Row: id (string), doctor_id (string), holiday_date (string/DATE), reason (string | null), created_at (string)
- Insert: id optional, doctor_id required, holiday_date required, reason optional, created_at optional
- Update: all optional

**medical_records table - fix fields:**
- Remove: `symptoms` (array)
- Add: `doctor_id` (string), `chief_complaint` (string | null)
- Keep: id, patient_id, appointment_id, visit_date, diagnosis, treatment_plan, vital_signs, notes, created_at, updated_at

**prescriptions table - fix fields:**
- Remove: `frequency`, `prescribed_at`, `updated_at`
- Add: `doctor_id` (string)
- Keep: id, medical_record_id, patient_id, medication_name, dosage, duration, instructions, created_at

**patient_files table - fix fields:**
- Remove: `medical_record_id`, `file_size`, `updated_at`
- Change: `file_type` to use FileType ('image' | 'pdf')
- Keep: id, patient_id, uploaded_by, file_name, file_path, description, created_at

**pregnancies table - fix fields:**
- Remove: `start_date`, `end_date`, `delivery_type`
- Add: `doctor_id` (string), `lmp_date` (string/DATE), `expected_due_date` (string/DATE, GENERATED)
- Status type: use the corrected PregnancyStatus
- Keep: id, patient_id, notes, created_at, updated_at

**pregnancy_measurements table - fix fields:**
- Remove: `blood_pressure_systolic`, `blood_pressure_diastolic`, `fundal_height_cm`, `fetal_heart_rate`
- Rename: `measurement_date` to `measured_at`
- Add: `gestational_week` (number | null), `weight_kg` (number | null), `blood_pressure` (string | null), `fetal_heartbeat` (number | null)
- Keep: id, pregnancy_id, notes, created_at

Keep the convenience type aliases at the bottom. Add new ones:
- `export type DoctorSchedule = Database['public']['Tables']['doctor_schedule']['Row']`
- `export type DoctorHoliday = Database['public']['Tables']['doctor_holidays']['Row']`

IMPORTANT: Preserve the `Database` interface structure (Row/Insert/Update for each table) and the `Json` type at the top. The Supabase client is typed with `Database`, so the structure must match.
