**Interface: TimeSlot**
```typescript
export interface TimeSlot {
  start: string   // ISO 8601 string (TIMESTAMPTZ for DB storage)
  end: string     // ISO 8601 string
  startDisplay: string  // "10:00 AM" for UI
  endDisplay: string    // "10:30 AM" for UI
}
```

**Function: generateAvailableSlots()**
Parameters:
- `date: Date` -- the target date
- `schedule: { start_time: string; end_time: string; slot_duration_minutes: number } | null` -- doctor's schedule for this day of week (null = not working)
- `existingAppointments: { scheduled_start: string; scheduled_end: string; status: string }[]` -- booked appointments for this date
- `holidays: { holiday_date: string }[]` -- all doctor holidays

Returns: `TimeSlot[]`

Algorithm:
1. Format date as 'yyyy-MM-dd' string. If it matches any holiday's `holiday_date`, return empty array.
2. If schedule is null, return empty array (doctor doesn't work this day).
3. Parse start_time and end_time (format "HH:MM") into hours/minutes.
4. Create `dayStart` Date object: date with start_time hours/minutes, set seconds/ms to 0.
5. Create `dayEnd` Date object: date with end_time hours/minutes.
6. **Filter past slots:** If the target date is today, set a `nowThreshold` to current time. Only include slots where start >= nowThreshold. Use `new Date()` for current time. Important: compare in local time context.
7. Loop: starting from dayStart, increment by slot_duration_minutes:
   - Calculate slotEnd = current + slot_duration_minutes
   - If slotEnd > dayEnd, break (slot doesn't fit)
   - Filter active appointments (status !== 'cancelled')
   - Check overlap: a slot overlaps an appointment if `slotStart < apptEnd AND apptStart < slotEnd`
   - If not overlapping any active appointment AND not before nowThreshold (if today), add to results
8. For each slot, compute:
   - `start`: `current.toISOString()` -- stores as UTC which is correct for TIMESTAMPTZ
   - `end`: `slotEnd.toISOString()`
   - `startDisplay`: `format(current, 'h:mm a')`
   - `endDisplay`: `format(slotEnd, 'h:mm a')`

**IMPORTANT timezone note:** The date parameter comes from the server component which constructs it from the selected date string. Since Jordan is UTC+3 (no DST), and the schedule times represent local times (e.g., "10:00" means 10 AM Amman time), we construct Date objects in the server's timezone context. The ISO strings stored in the DB are TIMESTAMPTZ and PostgreSQL handles the conversion. The key insight is that the server runs in a consistent timezone context, and the DB exclusion constraint compares TIMESTAMPTZ values correctly regardless of timezone representation.

**Edge cases to handle:**
- Empty schedule (null) -> return []
- Holiday date match -> return []
- No appointments -> return all slots
- All slots booked -> return []
- Today with past times -> filter out past slots

**Action 1: bookAppointment(formData: FormData)**
Zod schema:
```typescript
const bookSchema = z.object({
  patient_id: z.string().uuid(),
  scheduled_start: z.string().datetime(),
  scheduled_end: z.string().datetime(),
  appointment_type: z.enum(['consultation', 'follow_up', 'prenatal', 'ultrasound', 'other']),
  notes: z.string().optional(),
})
```

Implementation:
1. Auth check: get user, verify role is 'doctor' or 'secretary'
2. Validate input with Zod
3. Get doctor_id via getDoctorId helper
4. Insert into appointments:
   ```
   { patient_id, doctor_id, scheduled_start, scheduled_end, appointment_type, notes, status: 'scheduled', created_by: user.id }
   ```
5. Catch error code '23P01' (exclusion_violation) -> return `{ error: 'slotTaken' }` (translation key)
6. Catch other errors -> return `{ error: error.message }`
7. On success: revalidatePath for '/doctor/appointments', '/secretary/appointments', '/patient/appointments'
8. Return `{ success: true, appointment }`

**Action 2: cancelAppointment(appointmentId: string, reason: string)**
1. Auth check: get user, verify role is 'doctor' or 'secretary'
2. Fetch appointment by id: select scheduled_start, status
3. If not found: return `{ error: 'Appointment not found' }`
4. If status is 'cancelled': return `{ error: 'Appointment is already cancelled' }`
5. **24-hour policy check:** Calculate hours until appointment: `(new Date(appointment.scheduled_start).getTime() - Date.now()) / (1000 * 60 * 60)`. If < 24, return `{ error: 'cancel24HourPolicy' }` (translation key)
6. Update appointment: set `status = 'cancelled'`, `cancellation_reason = reason`
7. revalidatePath for all three appointment routes
8. Return `{ success: true }`

**Action 3: getAvailableSlots(date: string, doctorId: string)**
This is a data-fetching action (not a mutation, but useful to call from client components).
1. Parse date string, determine day_of_week via `new Date(date).getDay()`
2. Fetch doctor_schedule for this doctor_id and day_of_week where is_active = true (.single())
3. Fetch doctor_holidays for this doctor_id
4. Fetch appointments for this doctor_id on this date (where scheduled_start between start and end of day, in +03:00 offset)
5. Call `generateAvailableSlots(new Date(date), schedule, appointments || [], holidays || [])`
6. Return `{ slots: TimeSlot[] }`

**Action 4: getAppointments(filters: { role: string, userId: string, status?: string, dateFrom?: string, dateTo?: string })**
For listing appointments. This can be a regular server function (not necessarily a form action).
1. Auth check
2. Build Supabase query on 'appointments' table
3. Join patient profile: `.select('*, patient:patients!inner(id, profiles:profiles!inner(full_name_ar, full_name_en))')`
   - Actually, since patients.id refs profiles.id, we need: `select('*, patients!inner(profiles!inner(full_name_ar, full_name_en))')` -- adjust the join syntax based on what Supabase supports. The key is to get patient name alongside appointment data.
4. If role is 'patient': filter by patient_id = userId
5. If status filter: add .eq('status', status)
6. If dateFrom: add .gte('scheduled_start', dateFrom)
7. If dateTo: add .lte('scheduled_start', dateTo)
8. Order by scheduled_start desc
9. Return appointments array

IMPORTANT: Use `createClient` from `@/lib/supabase/server` for all queries. Import `generateAvailableSlots` from `@/lib/utils/slots`. Import types from `@/lib/types/database`.
