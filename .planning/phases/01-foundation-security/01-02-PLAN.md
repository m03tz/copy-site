    **Tables to create (in order due to foreign key dependencies):**

    1. **profiles** - Extends auth.users with role and personal info
       - id UUID PK references auth.users(id) ON DELETE CASCADE
       - role TEXT NOT NULL CHECK (role IN ('patient', 'doctor', 'secretary'))
       - full_name_ar TEXT NOT NULL
       - full_name_en TEXT
       - phone TEXT NOT NULL UNIQUE
       - email TEXT UNIQUE
       - created_at TIMESTAMPTZ DEFAULT NOW()
       - updated_at TIMESTAMPTZ DEFAULT NOW()

    2. **patients** - Additional patient-specific data
       - id UUID PK references profiles(id) ON DELETE CASCADE
       - date_of_birth DATE NOT NULL
       - blood_type TEXT CHECK (blood_type IN ('A+','A-','B+','B-','AB+','AB-','O+','O-'))
       - national_id TEXT UNIQUE
       - emergency_contact_name TEXT
       - emergency_contact_phone TEXT
       - notes TEXT
       - created_at TIMESTAMPTZ DEFAULT NOW()

    3. **doctor_schedule** - Doctor's working hours and holidays
       - id UUID PK DEFAULT gen_random_uuid()
       - doctor_id UUID NOT NULL REFERENCES profiles(id)
       - day_of_week INT CHECK (day_of_week BETWEEN 0 AND 6) -- 0=Sunday
       - start_time TIME NOT NULL
       - end_time TIME NOT NULL
       - slot_duration_minutes INT NOT NULL DEFAULT 30
       - is_active BOOLEAN DEFAULT true
       - created_at TIMESTAMPTZ DEFAULT NOW()
       - UNIQUE(doctor_id, day_of_week)

    4. **doctor_holidays** - Days the doctor is off
       - id UUID PK DEFAULT gen_random_uuid()
       - doctor_id UUID NOT NULL REFERENCES profiles(id)
       - holiday_date DATE NOT NULL
       - reason TEXT
       - created_at TIMESTAMPTZ DEFAULT NOW()
       - UNIQUE(doctor_id, holiday_date)

    5. **appointments** - Scheduled appointments with overlap prevention
       - id UUID PK DEFAULT gen_random_uuid()
       - patient_id UUID NOT NULL REFERENCES patients(id) ON DELETE CASCADE
       - doctor_id UUID NOT NULL REFERENCES profiles(id)
       - scheduled_start TIMESTAMPTZ NOT NULL
       - scheduled_end TIMESTAMPTZ NOT NULL
       - status TEXT NOT NULL CHECK (status IN ('scheduled', 'confirmed', 'cancelled', 'completed')) DEFAULT 'scheduled'
       - appointment_type TEXT NOT NULL CHECK (appointment_type IN ('consultation', 'follow_up', 'prenatal', 'ultrasound', 'other'))
       - cancellation_reason TEXT
       - notes TEXT
       - created_by UUID REFERENCES profiles(id)
       - created_at TIMESTAMPTZ DEFAULT NOW()
       - updated_at TIMESTAMPTZ DEFAULT NOW()
       - EXCLUDE USING gist (doctor_id WITH =, tstzrange(scheduled_start, scheduled_end) WITH &&) WHERE (status != 'cancelled')
       NOTE: The gist exclusion constraint requires the btree_gist extension. Add `CREATE EXTENSION IF NOT EXISTS btree_gist;` at the top of the migration.

    6. **medical_records** - Visit records with clinical notes
       - id UUID PK DEFAULT gen_random_uuid()
       - patient_id UUID NOT NULL REFERENCES patients(id) ON DELETE CASCADE
       - appointment_id UUID REFERENCES appointments(id)
       - doctor_id UUID NOT NULL REFERENCES profiles(id)
       - visit_date DATE NOT NULL DEFAULT CURRENT_DATE
       - chief_complaint TEXT
       - diagnosis TEXT
       - treatment_plan TEXT
       - vital_signs JSONB -- {bp, temp, weight, height, etc.}
       - notes TEXT
       - created_at TIMESTAMPTZ DEFAULT NOW()
       - updated_at TIMESTAMPTZ DEFAULT NOW()

    7. **prescriptions** - Linked to medical records
       - id UUID PK DEFAULT gen_random_uuid()
       - medical_record_id UUID NOT NULL REFERENCES medical_records(id) ON DELETE CASCADE
       - patient_id UUID NOT NULL REFERENCES patients(id)
       - doctor_id UUID NOT NULL REFERENCES profiles(id)
       - medication_name TEXT NOT NULL
       - dosage TEXT NOT NULL
       - duration TEXT NOT NULL
       - instructions TEXT
       - created_at TIMESTAMPTZ DEFAULT NOW()

    8. **patient_files** - Image/PDF uploads
       - id UUID PK DEFAULT gen_random_uuid()
       - patient_id UUID NOT NULL REFERENCES patients(id) ON DELETE CASCADE
       - uploaded_by UUID NOT NULL REFERENCES profiles(id)
       - file_name TEXT NOT NULL
       - file_type TEXT NOT NULL CHECK (file_type IN ('image', 'pdf'))
       - file_path TEXT NOT NULL -- Supabase Storage path
       - description TEXT
       - created_at TIMESTAMPTZ DEFAULT NOW()

    9. **pregnancies** - Pregnancy tracking
       - id UUID PK DEFAULT gen_random_uuid()
       - patient_id UUID NOT NULL REFERENCES patients(id) ON DELETE CASCADE
       - doctor_id UUID NOT NULL REFERENCES profiles(id)
       - lmp_date DATE NOT NULL -- Last Menstrual Period
       - expected_due_date DATE GENERATED ALWAYS AS (lmp_date + INTERVAL '280 days') STORED
       - status TEXT NOT NULL CHECK (status IN ('active', 'delivered', 'miscarriage', 'ectopic')) DEFAULT 'active'
       - notes TEXT
       - created_at TIMESTAMPTZ DEFAULT NOW()
       - updated_at TIMESTAMPTZ DEFAULT NOW()

    10. **pregnancy_measurements** - Per-visit measurements
        - id UUID PK DEFAULT gen_random_uuid()
        - pregnancy_id UUID NOT NULL REFERENCES pregnancies(id) ON DELETE CASCADE
        - measured_at DATE NOT NULL DEFAULT CURRENT_DATE
        - gestational_week INT
        - weight_kg DECIMAL(5,2)
        - blood_pressure TEXT -- e.g., "120/80"
        - fetal_heartbeat INT -- bpm
        - notes TEXT
        - created_at TIMESTAMPTZ DEFAULT NOW()

    Also create a helper function:
    ```sql
    CREATE OR REPLACE FUNCTION get_user_role()
    RETURNS TEXT AS $$
      SELECT role FROM public.profiles WHERE id = auth.uid();
    $$ LANGUAGE SQL STABLE SECURITY DEFINER;
    ```

    And an updated_at trigger function:
    ```sql
    CREATE OR REPLACE FUNCTION update_updated_at()
    RETURNS TRIGGER AS $$
    BEGIN
      NEW.updated_at = NOW();
      RETURN NEW;
    END;
    $$ LANGUAGE plpgsql;
    ```
    Apply this trigger to profiles, appointments, medical_records, and pregnancies tables.

    Start the file with: `CREATE EXTENSION IF NOT EXISTS btree_gist;`

<task type="auto">
  <name>Task 2: Add RLS policies and performance indexes</name>
  <files>supabase/migrations/00001_initial_schema.sql</files>
  <action>
    Append to the SAME migration file (after all CREATE TABLE statements). This is in the same file because RLS must be applied immediately after table creation.

    **1. Enable RLS on ALL tables:**
    ```sql
    ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
    ALTER TABLE patients ENABLE ROW LEVEL SECURITY;
    ALTER TABLE doctor_schedule ENABLE ROW LEVEL SECURITY;
    ALTER TABLE doctor_holidays ENABLE ROW LEVEL SECURITY;
    ALTER TABLE appointments ENABLE ROW LEVEL SECURITY;
    ALTER TABLE medical_records ENABLE ROW LEVEL SECURITY;
    ALTER TABLE prescriptions ENABLE ROW LEVEL SECURITY;
    ALTER TABLE patient_files ENABLE ROW LEVEL SECURITY;
    ALTER TABLE pregnancies ENABLE ROW LEVEL SECURITY;
    ALTER TABLE pregnancy_measurements ENABLE ROW LEVEL SECURITY;
    ```

    **2. RLS Policies (follow the research pattern -- wrap role checks in SELECT for caching):**

    **profiles:**
    - ALL users view own profile (SELECT): `id = auth.uid()`
    - Doctor/secretary view all profiles (SELECT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Users update own profile BUT cannot change role (UPDATE): `id = auth.uid()` WITH CHECK `role = (SELECT role FROM profiles WHERE id = auth.uid())`
    - Doctor/secretary insert profiles (INSERT): `(SELECT get_user_role()) IN ('doctor', 'secretary')` -- for creating patient accounts

    **patients:**
    - Patient views own record (SELECT): `id = auth.uid()`
    - Doctor/secretary view all patients (SELECT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Doctor/secretary create patients (INSERT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Doctor/secretary update patients (UPDATE): `(SELECT get_user_role()) IN ('doctor', 'secretary')`

    **doctor_schedule:**
    - Anyone authenticated can view schedule (SELECT): `true` (needed for booking)
    - Only doctor can manage schedule (INSERT/UPDATE/DELETE): `(SELECT get_user_role()) = 'doctor'`

    **doctor_holidays:**
    - Anyone authenticated can view holidays (SELECT): `true` (needed for booking)
    - Only doctor can manage holidays (INSERT/UPDATE/DELETE): `(SELECT get_user_role()) = 'doctor'`

    **appointments:**
    - Patient views own appointments (SELECT): `patient_id = auth.uid()`
    - Doctor/secretary view all appointments (SELECT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Doctor/secretary create appointments (INSERT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Doctor/secretary update appointments (UPDATE): `(SELECT get_user_role()) IN ('doctor', 'secretary')`

    **medical_records:**
    - Patient views own records (SELECT): `patient_id = auth.uid()`
    - Doctor manages all records (ALL): `(SELECT get_user_role()) = 'doctor'`
    - Secretary has NO access (no policy)

    **prescriptions:**
    - Patient views own prescriptions (SELECT): `patient_id = auth.uid()`
    - Doctor manages all prescriptions (ALL): `(SELECT get_user_role()) = 'doctor'`
    - Secretary has NO access

    **patient_files:**
    - Patient views own files (SELECT): `patient_id = auth.uid()`
    - Doctor/secretary view all files (SELECT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Doctor/secretary upload files (INSERT): `(SELECT get_user_role()) IN ('doctor', 'secretary')`
    - Doctor can delete files (DELETE): `(SELECT get_user_role()) = 'doctor'`

    **pregnancies:**
    - Patient views own pregnancies (SELECT): `patient_id = auth.uid()`
    - Doctor manages all pregnancies (ALL): `(SELECT get_user_role()) = 'doctor'`

    **pregnancy_measurements:**
    - Patient views own measurements (SELECT): `(SELECT patient_id FROM pregnancies WHERE id = pregnancy_id) = auth.uid()`
    - Doctor manages all measurements (ALL): `(SELECT get_user_role()) = 'doctor'`

    **3. Performance indexes (CRITICAL for RLS):**
    ```sql
    -- Profile lookups (used in every RLS policy via get_user_role())
    CREATE INDEX idx_profiles_id_role ON profiles(id, role);

    -- Patient data access
    CREATE INDEX idx_patients_id ON patients(id);

    -- Appointment lookups
    CREATE INDEX idx_appointments_patient_id ON appointments(patient_id);
    CREATE INDEX idx_appointments_doctor_id ON appointments(doctor_id);
    CREATE INDEX idx_appointments_scheduled_start ON appointments(scheduled_start);
    CREATE INDEX idx_appointments_status ON appointments(status);

    -- Medical records
    CREATE INDEX idx_medical_records_patient_id ON medical_records(patient_id);
    CREATE INDEX idx_medical_records_doctor_id ON medical_records(doctor_id);
    CREATE INDEX idx_medical_records_appointment_id ON medical_records(appointment_id);

    -- Prescriptions
    CREATE INDEX idx_prescriptions_patient_id ON prescriptions(patient_id);
    CREATE INDEX idx_prescriptions_medical_record_id ON prescriptions(medical_record_id);

    -- Patient files
    CREATE INDEX idx_patient_files_patient_id ON patient_files(patient_id);

    -- Pregnancies
    CREATE INDEX idx_pregnancies_patient_id ON pregnancies(patient_id);
    CREATE INDEX idx_pregnancies_status ON pregnancies(status);

    -- Pregnancy measurements
    CREATE INDEX idx_pregnancy_measurements_pregnancy_id ON pregnancy_measurements(pregnancy_id);

    -- Doctor schedule
    CREATE INDEX idx_doctor_schedule_doctor_id ON doctor_schedule(doctor_id);
    CREATE INDEX idx_doctor_holidays_doctor_id ON doctor_holidays(doctor_id);
    CREATE INDEX idx_doctor_holidays_date ON doctor_holidays(holiday_date);
    ```

    IMPORTANT: Every column used in a RLS policy USING clause MUST have an index. This prevents the 100x performance degradation documented in research.
    IMPORTANT: Wrap all role-check subqueries in the (SELECT ...) pattern to enable PostgreSQL query-level caching (called once per query, not per row).
  </action>
